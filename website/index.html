Why Android? Hardware decides.

Android phones span an enormous range of CPUs, memory, storage, and thermal behavior. A model that flies on one phone may crawl on another — so EdgeFit starts from your measured hardware, not a leaderboard.

What EdgeFit does

Hardware-aware model selection

Profiles your phone and recommends compatible local LLM candidates with explicit compatibility estimates.

Real on-device benchmarking

Runs genuine llama.cpp inference on the phone and records measured throughput with thermal and memory conditions.

Meta Muse Spark predictions

Predicts inference speed before each measurement, with uncertainty — then the phone checks the answer.

Predicted vs measured

Every prediction is stored first; error is computed deterministically by the host, never narrated by the model.

Agentic optimization, gated

Bounded experiment proposals with explicit approve / reject and a fixed attempt budget. Nothing auto-runs.

Privacy-first sharing

Results stay on-device until you approve per-submission sharing. Global aggregates publish only above quorum.

How EdgeFit AI Works

One picture of the whole system — from your phone to public evidence. This is Walkthrough v1.1, Fig 02, drawn from the shipped sources:

  1. 1Read actual device constraints — CPU, memory, ABI, thermal state.
  2. 2Evaluate model suitability against the offline catalog, with explicit uncertainty.
  3. 3Run native llama.cpp inference benchmarks on the phone.
  4. 4Validate and preserve each measurement as hashed on-device evidence.
  5. 5Optionally use Meta Muse Spark for bounded prediction and owner-approved experiments.
  6. 6Contribute evidence to the Global network only with explicit consent.

The Android workflow

  1. 1Select a GGUF model file on the phone.
  2. 2Configure inference: context, threads, prediction length.
  3. 3Run a physical benchmark; results stay on-device.
  4. 4Review measured throughput per session.
  5. 5Optionally contribute with explicit consent (genuine uploads flowing under consent approval — see live counts on the dashboard).

Meta Muse Spark, honestly scoped

EdgeFit uses Meta's Muse Spark model to help analyze validated evidence: predictions before measurement, evidence-grounded follow-ups, and bounded optimization proposals — every one behind explicit human authorization. A validated tool request runs one fixed read-only query over local SQLite, and the model reasons over the returned rows. No live model outputs are shown on this site, and nothing here implies endorsement by Meta.

More than a static demo: technical evidence

Six-run physical study measured

Galaxy S22 Ultra, fixed workload: 4-thread median 16.52 tok/s vs 8-thread median 10.49 tok/s (n=3 each, exploratory, one device). Muse correctly abstained rather than guess beyond the evidence (fabricated-citation rate 0.0). Full artifacts, frozen manifests, and methodology live in the source repository, with reproducible offline test suites.

Global evidence, gated by proof

The long-term goal is a global network where only verified, consented, comparable phone measurements count. Genuine contributions are flowing (see live counts on the dashboard), but zero verified global aggregates are published yet. The evidence status page tracks exactly what exists and what publication requires.
